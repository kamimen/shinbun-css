## 1. 目的と適用範囲

日本語の新聞紙面に特徴的な次の要素を、CSS だけで Web ページに再現する。

- 縦組み（右から左へ行が進む）と横組み。縦組みと横組みは、同じ段グリッドを 90 度回したものとして扱う
- 紙面を区切る**段**のグリッドと、記事の座標指定による長方形の敷き詰め
- 記事ごとの、n 段を占める矩形と、その中での段ごとの本文の流れ
- 記事の全段にまたがる**段抜き**の見出しと、横向きに組む**横見出し**
- 題字、肩見出し・主見出し・袖見出し・脇見出し、リード（前文）、発信地、署名、写真、囲み、コラム、表、広告枠

次のものは対象外とする（§12）。

- 特定の新聞社の紙面デザイン、書体、ロゴの複製。題字は、利用者が自分の文字やロゴを入れる枠として提供する
- 日本語組版そのものの完全な実装（行の調整、約物の詳細な処理など）。これは JLReq / JIS X 4051 を実装するブラウザの責務とし、本ライブラリはブラウザの機能を適切に指定するにとどまる
- 記事の自動配置（紙面割付）。記事が占める段数と位置は、文書の作者が指定する

## 2. 参照規格

出典のリンクは [REFERENCES.md](REFERENCES.md) にある。本文に「（B）」などと書いたものは、その章を指す。

### 2.1 日本語組版の規格

| 略称 | 名称 | 本ライブラリでの位置づけ |
|---|---|---|
| JLReq | 日本語組版処理の要件（W3C Working Group Note, 2020-08-11, 日本語版） | 用語と設計の主な根拠。以下の節番号はこの版のもの |
| JIS X 4051 | 日本語文書の組版方法（2004） | JLReq が主な根拠とする規格。本文は[kikakurui.com](https://kikakurui.com/x4/X4051-2004-02.html)で読んだ。§9.1 に、読んだ箇条との対応を載せる。**新聞を対象とした規格ではなく**（7.4.1 は文字サイズ 8〜11 ポ・12〜16 Q を原則とする）、**本ライブラリは適合を主張しない** |

JLReq は、主に書籍を対象とすると自ら述べている（§1.3）。雑誌、マニュアル、Web 上の文書は今後の課題としている。**新聞を対象とした規格ではない**。

**新聞の紙面全体を定める、単一の公開された規格や企画書は、調査した範囲では確認できなかった**。新聞固有の事柄は、各社の社内基準と業界の慣習に拠る。実務の解説（朝日新聞 NIE、印刷会社の編集サポート、整理の用語集など）を読み、§3 と §10 に出典つきでまとめた。

| `text-wrap: balance`、`text-autospace`、`text-spacing-trim` | CSS Text Level 4 |

CSS Multi-column Layout Module **Level 2**（`column-height`、`column-wrap`、`column-span` の整数指定）は、Editor's Draft に `column-span` の整数指定の未解決の論点が書かれており、Chrome 154 でも `column-span: 2` は使えない。`column-height` と `column-wrap` は Chrome 145 から使えるが、Firefox と Safari は未対応である。本ライブラリは Level 2 の機能に依存しない（§12）。

## 3. 用語と定義

出典のリンクは [REFERENCES.md](REFERENCES.md)。表の「出典」欄の（B）〜（E）は、その章を指す。

### 3.1 組版の用語（JLReq の用語集による）

JLReq の用語集（[§G](https://www.w3.org/TR/jlreq/#appendix_7)）は、JIS Z 8125 または JIS X 4051 の定義を採用している。次はその定義を、本ライブラリで使う語について要約したもの。

| 用語 | 読み | 定義 | 本ライブラリ |
|---|---|---|---|
| 縦組 | たてぐみ | 行においては文字を上から下へ、ページにおいては**行を右から左へ、段を上から下へ**配列すること | 既定 |
| 横組 | よこぐみ | 行においては文字を左から右へ、ページにおいては**行を上から下へ、段を左から右へ**配列すること | `data-sb-writing="horizontal"` |
| 段組 | だんぐみ | 連続する 1 系列の文章を 1 ページの中で、字詰め方向において 2 つ以上の部分（段）に分割し、各部分の間に空白（段間）を設けて文字を配置する方法 | `.sb-article` の内部 |
| 段 | だん | 段組において、分割された 1 区分 | `--sb-dan`、`--sb-span` |
| 段間 | だんかん | 段組の段と段との間の空き | `--sb-gap` |
| 段抜き | だんぬき | 段組のページにおいて、見出し、図版などを複数段にまたがって配置すること | 見出し類・写真・囲みの `column-span: all` |
| 版面 | はんめん | 本の 1 ページ内の、周囲の余白を除いた部分の印刷面（柱とノンブルは含めない） | `.sb-page` |
| 基本版面 | きほんはんめん | 本の基本として設計される版面体裁。組方向、段数、文字サイズ、字詰め数、行数、行間及び段間で指定する | トークン（§6） |
| 行長 | ぎょうちょう | 基本版面で設定した行の行頭から行末までの長さ | `--sb-chars` × `--sb-fs` |
| 行送り | ぎょうおくり | 隣接する行同士の基準点から基準点までの距離 | `--sb-lh` |
| 行間 | ぎょうかん | 隣接する行の文字の外枠間の距離 | `--sb-lh` − 1 |
| 字下げ | じさげ | 行頭の位置を行末方向に移すこと。段落先頭行の字下げは、原則として、その段落で使用している文字サイズの全角アキ（JLReq 3.5.1） | 本文の `<p>` |
| 天付き | てんづき | 段落最初の行で、行頭の字下げを行わず、隣接する行の行頭とそろえること | `.sb-flush` |
| 縦中横 | たてちゅうよこ | 縦組の行中で、文字を縦向きのまま横組にすること。縦組では、主に 2 桁の数字などで利用されている（JLReq 2.3.2） | `.sb-tcy` |
| 禁則処理 | きんそくしょり | 行頭禁則、行末禁則、分離（分割）禁止などの禁則を避けるために行われる処理 | `line-break: strict` |
| 詰め組み | つめぐみ | ベタ組より字送りを詰めて文字を配置する方法。書籍では、大きな文字サイズの見出しで採用されている例がある（JLReq 2.1.3） | 見出しの `palt`、`vpal` |
| 柱 | はしら | 各ページの版面外に記載された書名・章名・節名など | （新聞の「欄外」は §3.2 の別項目） |

JLReq 2.3.1 は、「大部数の新聞のすべては縦組である」と述べている。

## 4. 紙面のモデルと HTML 構造

```
.sb-paper                        紙面（根。トークンと組方向を持つ）
├─ .sb-masthead                  題字の帯（横組み。任意）
├─ .sb-folio                     欄外（面名・日付などの行。任意）
└─ .sb-page                      紙面領域（段グリッド）。座標指定は .sb-page--grid
   ├─ .sb-nameplate              題字（枠。文字でもロゴでもよい）
   ├─ .sb-yoko                   横見出し
   ├─ .sb-article × n            記事（n 段を占める矩形）
   │  ├─ .sb-kicker              肩見出し（任意）
   │  ├─ .sb-headline            主見出し
   │  ├─ .sb-sleeve              袖見出し（任意）
   │  ├─ .sb-sub                 脇見出し（任意）
   │  ├─ .sb-dateline            発信地（任意）
   │  ├─ .sb-lead                リード
   │  ├─ <p>…                    本文
   │  ├─ .sb-photo               写真（任意）
   │  ├─ .sb-box                 囲み（任意）
   │  └─ .sb-byline              署名（任意）
   ├─ .sb-photo                  写真（紙面に直接置く場合）
   ├─ .sb-box                    囲み（紙面に直接置く場合）
   ├─ .sb-table                  表（番組表・市況など）
   └─ .sb-ad                     広告枠
```

適合する文書は、次を満たさなければならない。

1. 紙面領域 `.sb-page` は `.sb-paper` の子孫でなければならない。
2. 紙面に配置するもの（記事、題字、横見出し、写真、囲み、表、広告枠）は、`.sb-page` の直接の子でなければならない。
3. 見出し類（`.sb-kicker`、`.sb-headline`、`.sb-sleeve`、`.sb-sub`）、写真 `.sb-photo`、囲み `.sb-box` を記事の内側で段抜きにするには、`.sb-article` の直接の子にしなければならない。入れ子にした場合は段抜きにならない。
4. 紙面に配置するものが占める段数は、`data-sb-span`（または `--sb-span`）で指定しなければならない。省略した場合は 3 段になる。
5. 座標指定（§7.2）で配置する場合は、`.sb-page` に `.sb-page--grid` を併用しなければならない。
6. 記事の本文は `<p>` でマークアップすべきである。

`.sb-masthead` と `.sb-folio` は、縦組みの紙面でも常に横組みで表示する。

`.sb-folio` は、朝日新聞 NIE の用語集が「欄外」（紙面最上部の外枠の上に表示する、その新聞に関する情報）と呼ぶものに当たる。`.sb-folio__section` は、紙面の上端に白抜き文字で示される面名に当たる。

## 5. 組方向

`.sb-paper` の `data-sb-writing` 属性で指定する。

| 値 | 意味 |
|---|---|
| （省略）または `vertical` | 縦組み。既定 |
| `horizontal` | 横組み |

JLReq の用語集の定義では、縦組みは「行を右から左へ、段を上から下へ」、横組みは「行を上から下へ、段を左から右へ」配列する。本ライブラリの縦組みと横組みは、同じクラス・同じ変数で書け、違いは次のとおり。

| | 縦組み | 横組み |
|---|---|---|
| 段の向き | 天地方向（段は上から下へ並ぶ） | 左右方向（段は左から右へ並ぶ） |
| 行軸 | 右から左 | 上から下 |
| 段数 | `--sb-dan`（既定 10） | `--sb-dan-h`（既定 6） |
| 段間の既定 | 1 字分 | 1.2 字分 |
| 写真の比率の既定 | `4 / 5` | `4 / 3` |
| 紙面の天地 | 段数から決まる。幅は内容（または行数）で決まる | 幅は親に従う。天地は内容で決まる |

画面の幅に応じて組方向を切り替えるには、`data-sb-responsive` 属性を使う（`src/shinbun.js` が必要）。値は切り替える幅（px）で、省略すると 768 とする。

縦組みの `.sb-page` は、幅が親を超える場合は横にスクロールする。Chrome 154 では、スクロールは右端から始まる。

## 6. 版面の設計（トークン）

JLReq の用語集は、基本版面を「組方向、段数、文字サイズ、字詰め数、行数、行間及び段間で指定する」と定義している。これと本ライブラリのカスタムプロパティの対応は次のとおり。

| 基本版面の指定 | カスタムプロパティ | 既定値 | 備考 |
|---|---|---|---|
| 組方向 | `data-sb-writing` 属性 | 縦組み | §5 |
| 段数 | `--sb-dan`、`--sb-dan-h` | `10`、`6` | 縦組み、横組みでの 1 ページの段数。横組みでは `--sb-dan` が `--sb-dan-h` の値になる |
| 文字サイズ | `--sb-fs` | `0.8rem` | 本文の 1 字の大きさ |
| 字詰め数 | `--sb-chars` | `10` | 縦組みでの 1 段の字数。行長は `--sb-chars` × `--sb-fs` |
| 行数 | `--sb-lines` | `36` | 座標指定グリッドでの、行軸方向の行数。座標指定でないときは使わない |
| 行間 | `--sb-lh` | `1.55` | 行送りの倍率。行間 = `--sb-lh` − 1（文字サイズに対する倍率） |
| 段間 | `--sb-gap` | `var(--sb-fs)`（1 字分） | 記事どうしのアキにも使う |
| 書体 | `--sb-font-body`、`--sb-font-gothic` | 明朝体系、ゴシック体系のフォント一覧 | |

プリセットのクラスとして、`.sb-paper--15dan`（15 段、1 段 10 字）と `.sb-paper--12dan`（12 段、1 段 12 字）を用意する。根拠は §10.2。

配置のカスタムプロパティは、`.sb-page` の直接の子の要素に指定する。`data-sb-*` 属性（§8.1）でも指定できる。

| カスタムプロパティ | 意味 | 既定 |
|---|---|---|
| `--sb-y` | 開始する段（1 から数える。縦組みでは上から、横組みでは左から） | 自動 |
| `--sb-span` | 占める段数 | 3 |
| `--sb-x` | 行軸の開始位置（1 から数える。縦組みでは右から、横組みでは上から） | 自動 |
| `--sb-w` | 行軸方向に占める行数 | 1（座標指定のときは必ず指定する） |

その他のカスタムプロパティは次のとおり。

| カスタムプロパティ | 用途 |
|---|---|
| `--sb-paper`、`--sb-ink`、`--sb-muted`、`--sb-rule`、`--sb-rule-soft`、`--sb-accent`、`--sb-photo-bg` | 色。`light-dark(明, 暗)` で定義する |
| `--sb-h-xl`、`--sb-h-l`、`--sb-h-m`、`--sb-h-s` | 見出しの大きさ（文字サイズに対する倍率） |
| `--sb-photo-ratio` | 写真の比率「幅 / 高さ」 |
| `--sb-pitch` | 行送りの実寸 `--sb-fs` × `--sb-lh`。座標指定の行の高さに使う |
| `--sb-track` | 内部用。縦組みでの 1 段の天地寸法 `--sb-chars` × `--sb-fs`。上書きしてはならない |

配色は `data-sb-theme` 属性で切り替える。

| 値 | 意味 |
|---|---|
| （省略）または `light` | 明るい配色 |
| `dark` | 暗い配色 |
| `auto` | OS の設定に従う |

## 7. 段グリッド（アルゴリズム）

### 7.1 共通の規則

`.sb-page` は、縦組み・横組みに共通する次の規則で構成する。

1. `.sb-page` を CSS グリッドコンテナにする。**段軸**は `grid-template-columns`、**行軸**は `grid-template-rows` が受け持つ。縦書きでは inline 軸が天地になるので、`grid-template-columns` が段を天地方向に並べる。
2. 段の数は `--sb-dan`。縦組みでは、1 段の天地寸法を `--sb-track`（= `--sb-chars` × `--sb-fs`）にし、`.sb-page` の天地を `--sb-dan` × `--sb-track` ＋ (`--sb-dan` − 1) × `--sb-gap` にする。横組みでは、各段の幅を等分する。
3. `.sb-page` の直接の子は、`--sb-y` から `--sb-span` 個の段、`--sb-x` から `--sb-w` 個の行を占める。
4. 記事 `.sb-article` の内部は、`--sb-span` 個の段組み（CSS Multi-column）にする。段の寸法は、記事の段軸方向の寸法と段間から決まり、縦組みでは `--sb-track` と一致する。
5. 本文は段ごとに、行軸の向きに行を進める。1 つの段がいっぱいになると、次の段（縦組みでは下、横組みでは右）の先頭から続く。
6. 見出し類・写真・囲みは `column-span: all` で、記事の全段にまたがる（段抜き）。本文は、段抜きの要素の後ろから始まる。
7. 記事の下端と、行軸の終端側（縦組みでは左端）に罫線を引く。罫線はアキの中央に引き、寸法を食わない。記事の中の段と段を区切る罫線（中段罫）は引かない。

### 7.2 配置の方式

| 方式 | 指定 | 行軸方向の大きさ | 用途 |
|---|---|---|---|
| 自動（既定） | `.sb-page` のみ | 内容で決まる | 位置を指定せず、記事を順に詰める簡易な組み方 |
| 座標指定 | `.sb-page` と `.sb-page--grid` | `--sb-lines` 行に固定 | 実際の新聞のように、記事を長方形に敷き詰める（ブロック組み） |

自動の方式では、`grid-auto-flow: row dense` で、行軸の始まりから記事を詰めて並べる。

座標指定の方式では、`.sb-page` の行軸方向を `--sb-lines` 行（1 行の寸法は `--sb-pitch`）に固定し、記事を指定した長方形の中に収める。記事の本文は、`column-fill: auto` で、指定した長方形の中を先頭の段から順に埋める。**収まらない本文は、段軸方向に新しい段として追加され、長方形の外にはみ出す**。はみ出しは `findOverflow()`（§8.3）で検出できる。文章を減らすか、段数や行数を増やして直す。

## 8. リファレンス

クラス、カスタムプロパティ、`data-` 属性、JavaScript の関数の一覧は、**[API.md](API.md)** にある。これらの定義は `src/manifest.json` に 1 か所だけ書き、API.md と、CSS の配置属性のセレクター（`data-sb-span` など）は、そこから `scripts/gen.mjs` が生成する。`npm test` は、マニフェストと CSS・JS・文書・例が食い違っていないか、生成物が最新かを検証する。

### 8.1 配置の書き方

`.sb-page` の直接の子の配置は、`data-sb-*` 属性で書く。

```html
<article data-sb-x="9" data-sb-w="16" data-sb-y="3" data-sb-span="5">…</article>
```

| 属性 | 意味 | 範囲 |
|---|---|---|
| `data-sb-span` | 占める段数 | 1〜15 |
| `data-sb-y` | 開始する段（縦組みでは上から、横組みでは左から） | 1〜15 |
| `data-sb-x` | 行軸の開始位置（縦組みでは右から、横組みでは上から） | 1〜60 |
| `data-sb-w` | 行軸方向に占める行数 | 1〜60 |

範囲の外の値や、計算した値を使うときは、同じ名前のカスタムプロパティ（`--sb-span`、`--sb-y`、`--sb-x`、`--sb-w`）をインラインの `style` に書く。インラインの指定が優先される。

### 8.2 クラスなしの素の HTML

`.sb-page` の中では、次の要素が、クラスなしで対応するクラスと同じ見た目になる。対応表は [API.md](API.md#クラスなしの素の-html) にある。

- `.sb-page > article` は記事（`.sb-article`）、その直下の `h2` は主見出し（`.sb-headline`）
- `.sb-page > header` は題字（`.sb-nameplate`）、その直下の `h1` は題字の文字
- `.sb-paper figure` は写真、`figcaption` はその説明文
- `.sb-paper aside` は囲み、`.sb-paper table` は表

肩見出し・袖見出し・脇見出し・リード・署名など、素の HTML に対応する要素がないものは、クラスを付ける。

### 8.3 JavaScript（任意）

CSS だけでも使える。`src/shinbun.js` は ES モジュールで、読み込むと `globalThis.Shinbun` にも入る。関数は [API.md](API.md#javascript) にある。

`autoTcy` の対象は、半角の数字がちょうど 2 桁続く部分とする。前後に数字がある場合（3 桁以上）や、小数点・桁区切りでつながる場合（3.14、1,234）は対象外とする。JLReq 2.3.2 は、縦中横が「主に 2 桁の数字などで利用されている」と述べ、日経の記事は、新聞では 2 桁の数字だけを縦中横にし、それ以外の桁数の数字は縦書きにすると述べている。CSS の `text-combine-upright: digits 2` が同じ指定だが、Chrome 154 は未対応で、MDN の互換性データにも `digits` は掲載されていない。

`findOverflow` は、記事の本文の範囲を実測して、記事の長方形の外に出ているかを判定する。罫線用の疑似要素は本文ではないので、判定に含めない。

### 9.1 JIS X 4051:2004 との対応

本文を読んだ箇条だけを挙げる（出典: [kikakurui.com](https://kikakurui.com/x4/X4051-2004-02.html)）。

| 箇条 | 規格の記述 | 本ライブラリ |
|---|---|---|
| 4.8 縦中横処理 | 縦書きの行中で、縦書きの字の向きのまま横書きになるように文字列を中央に配置する | `.sb-tcy`（`text-combine-upright: all`）、`autoTcy` |
| 7.3 とじの方向 | 縦書きは右とじ、横書きは左とじ。縦書きでブロック類を横向きに回転させる場合は右回りに 90° | 右とじ・左とじは扱わない。回転は `.sb-sideways`（`text-orientation: sideways`）で、向きの検証はしていない |
| 7.4.1 f) 段間 | 段間は文字サイズの 2 倍アキが既定値。変える場合は 1.5 倍以上 3 倍以下が望ましい | `--sb-gap` で指定する。既定値はこの規格に合わせていない |
| 7.4.1 c) 字詰め数 | 縦書きは 15 字以上 52 字以下、横書きは 15 字以上 40 字以下が望ましい | 新聞の 1 行字数（§10.2）とは範囲が異なる。`--sb-chars` の既定値は 10 |
| 7.4.2 版面及び段の寸法 | 版面の字詰め方向の寸法 ＝ 1 段の字詰め数 × 文字サイズ × 段数 ＋ 段間 × (段数 − 1) | 段の寸法は `--sb-chars`・`--sb-fs` から算出する（§6） |
| 7.4.4 c) 段の配置 | 縦書きの版面の各段は上から下、横書きは左から右 | §5、§7 のとおり |
| 8.3.3 f) 段抜きの別行見出し | 指定段数N段の字詰め方向の長さ ＝ 1 段の字詰め数 × 文字サイズ × N ＋ 段間 × (N − 1)。基本版面の段数と同じなら先頭の段から始め、少なければ位置により前の段か出現した段から始める。直前の各段の行数はそろえる | 全段の段抜きだけを `column-span: all` で行う（§9 の段抜きの行と同じ） |

### 10.2 段と段数と 1 行の字数

新聞広告ナビは、段を次のように説明している。新聞紙面の記事は「段」というブロックで構成され、もともとは 1 ページの縦幅を 15 分割したブロックが「1 段」である。この段を元に記事や写真をレイアウトし、広告も段を単位に縦のサイズを表す。12 段組が登場し、1 段のサイズは 1/15 から 1/12 になったが、広告は今までの 15 段組で料金を算出している。

日本新聞協会の「新聞協会報・紙面展望　12 段制へ踏み出す」（2009-01-01）は、2008 年の状況を次のように報告している。

- 2008 年は、文字拡大と段数変更が相次いだ。長らく続いた 15 段が圧倒的多数という状況からの転換の年となった。目的は、高齢者にも若者にも読みやすい紙面作りである。
- 『新聞技術』204 号の調査（2008 年 4 月現在）では、2007 年から 2008 年春に文字拡大を図ったのは、予定を含め 71 紙。そのうち 29 紙が 12 段制に移行または移行予定だった。
- **1 行の字数**は、対応が分かれた。

| 制度 | 1 行の字数 | 紙数 |
|---|---|---|
| 12 段制 | 12 字 | 14 紙 |
| 12 段制 | 13 字 | 15 紙 |
| 15 段制 | 10 字 | 35 紙 |
| 15 段制 | 11 字 | 25 紙 |

- 毎日新聞は 2007 年 12 月に「J 字」で先行し、15 段制を維持しながら 1 行を 11 字から 10 字にした。朝日新聞と読売新聞は、2008 年 3 月から 12 段制に移行した。

そのほか、次の記述がある。

- 日経本紙は縦 15 段、横は 130 文字幅（日経 note、2018 年）。
- 中日新聞系の 4 紙（中日、東京、北陸中日、日刊県民福井）は 2014 年 1 月 1 日から 12 段制を導入し、1 行 10 字から 12 字に増やした。北國新聞、宇部日報も同日に移行した（宣伝会議、2014 年）。
- 実際の紙面は 12 段の構成が大半で、広告は変わらず 15 段で計算するのが一般的（アドクロ、2025 年）。

プリセット `.sb-paper--15dan`（1 行 10 字）と `.sb-paper--12dan`（1 行 12 字）は、2008 年の調査で、それぞれの制度で最も多かった組み合わせ（15 段制で 10 字が 35 紙、12 段制で 12 字が 14 紙）に基づく。

### 10.3 文字の大きさ

朝日新聞は、現在の記事の文字を縦 3.3mm、横 3.9mm の、やや横に膨らませた扁平文字としている（2011 年から。「いろんな数字編」）。1888 年の創刊時は 10.5 ポイント（3.7mm 角）、1940 年には 6.3 ポイント（2.2mm 角）まで縮小し、翌年に横幅だけ 2.5mm に伸ばした扁平文字が登場した。

日経 note は、日経が「Z 字」と呼ばれる扁平文字を使い、1 文字が 119 × 143 ミルスと決まっていると述べている。

本ライブラリの文字は、書体どおりの比率（扁平にしない）で組む。

### 10.4 見出し

- 見出しの名称（肩・主・袖・柱）と構成は、あかつき印刷、運輸労連、パーソナル編集長、朝日 NIE で一致する。
- 見出しは、柱見出し、肩見出し、主見出し、袖見出しの 4 本で構成する。ただし現在は、**主見出しと袖見出しの 2 本が基本型**として一般化している。柱見出しや肩見出しは、記事の内容や紙面構成によって加える（あかつき印刷、運輸労連）。
- 柱見出しは、関連する記事を一つの紙面に載せるときに、全体のテーマを示す。**1 つの紙面に 1 か所にとどめる**（あかつき印刷）。
- 字数の基準は、**主見出し 7〜8 字、袖見出し 10〜11 字**（「主見出し 8 字・袖 10 字」）（あかつき印刷）。京都新聞 note は、従来は「主見出し 8 本、脇見出し 10 本」を叩き込まれたが、近年はニュースの核となるキーワードを取りこぼさないために、字数制限をある程度無視してもよいという考え方に変わったと述べている。
- 一つの紙面に見出しが 10 本あるとすれば、基本型が 8 本、変型は 2 本程度にとどめる。最低でも 1 つは大胆に変化させた見出しも必要（あかつき印刷）。
- 主見出しを特別に大きくするのは、一つの紙面に 1 本程度にとどめると効果的（あかつき印刷）。
- 見出しの天地のアキが少なくぎっしりつまったものを「ハリの強い見出し」、アキがありすぎるものを「ハリの弱い見出し」という（あかつき印刷）。
- 横見出しの左右の空白は、横見出しの中で一番大きな文字の半分を、左右にあける。したがって左右の幅は、主見出しの字数に 1 字分を加えたものになる（あかつき印刷）。
- 中見出しは、普通 1 段、特殊でも 2 段が最大。複数入れるときは、字数・文字の大きさ・形を統一する（あかつき印刷）。
- 漢字ばかりの見出しは「戒名見出し」といい、禁じ手とされる。1 字以上のかなを入れる（あかつき印刷、京都新聞 note）。
- 見出しは明朝体を主体にして、ゴシック体は部分的に使う（あかつき印刷）。
- 一つの見出しに、洋数字と和数字を混用しない（あかつき印刷）。
- 見出しには、1 面で重要度に応じて「右から左」あるいは「上から下」へ記事を配置する（朝日 vol.02）。

本ライブラリは、見出しを個別のクラスとして提供する。位置と字数は、作者が決める。

### 10.5 縦中横

新聞では 2 桁の数字だけを縦中横にし、それ以外の桁数の数字は縦に並べる（日経 note）。§8.3 の `autoTcy` がこの慣習に従う。

### 10.8 紙面づくりの定石

あかつき印刷の「紙面レイアウトの基本と応用」は、縦書きの新聞のレイアウトの定石を次のように述べている。

- **視線の流れ**: 縦書きは、上から下へ、右から左へ行を読む。読者の視線も習慣的にそう流れるため、紙面では「右から左下がりの対角線」が最も目立つ。この対角線の外、つまり**紙面の左上と右下は「死角」**で、目立ちにくい。
- **定石**: 死角に、囲みやタタミなどの「ハコもの」、写真、イラストを置いて死角を生かす。右上から左下の対角線上に見出しが配置できるよう考えながら記事を流し、最も重要な記事、読ませたい記事を、そのつぎに配置して、左下でまとめる。
- **押えて流す手法**: ハコもの、写真、毎号連載しているものを、それぞれの位置と形・大きさを決めて固定した間を、右から左へ、上から下へ、見出しを配置しながら、水が流れるように記事を流す。これが紙面の定石（基本）である。読者は、必ずしもトップ記事から順に読むとは限らないので、どの記事から読み始めても、流れは自然でなければならない。
- **流れの原則**: 記事はぶつかったら下段へと流れるもので、何かを飛びこえて流れるものではない。例外は、①カコミ・タタミで見出しが真ん中にあるとき、②さし絵を使うとき、③記事の中に広告やカットを入れたとき。
- **割付の順序**: 素材（記事、写真、イラスト）を頭に入れる → どの記事と写真をどの面に入れるかを決める（面割）→ 記事の価値を評価しながら紙面の構図をスケッチする（思いきって「形」を優先する）→ 連載ものは、同じ面の同じ位置に、同じような形で、最初に決める → 連載やカコミ・タタミの大きさを正確に計算して、位置と大きさを書き入れる → 流し記事を流す。**見出しは、天地何段でどの位置に入るかが決まったあとで、それに合わせて文章や形を考える（見出しは最後）。**
- **左右のバランス**: 新聞を広げたときの左右の紙面が、全体としてバランスがとれていないと、チグハグな感じを与える。左右の紙面のつりあいを考える。
- **ブロック組み**: 週刊や旬刊のタブロイド判では、ハコものを多く使った「ブロック組み」の紙面も大切。定型はなく、大きなブロックで大胆に組むとすっきりする。字詰や行数の計算、飾り罫の天地・左右の空白の計算を正確に行う。罫のスペースは必ず計算に入れる（例: 飾り罫が入る記事は、字詰を基本字詰より 1 字減らす）。正確な行数計算をしたうえで、紙面の左右どちらかに「逃げ道」をつくる（幅が 1〜2 行ずれても調整できる場所）。

朝日新聞 NIE の用語集は、流し組みを、主な記事の文章が右上から左下に向かって流れ、次の記事の見出しにぶつかると下の段に跳ね返って進む組み付け方とし、大きさの異なる見出しや写真を紙面の対角線上に X 型に配置するのが代表的なレイアウトとしている。これに対して、一つ一つの記事を四角く区切り、ブロックのように並べていく手法を「ブロック組み」という。パーソナル編集長の用語集は、X 型、T 型（紙面の最上段に横書きの大きな見出しを置き、中央にも縦の見出しを置く）、区画型（箱組型）のレイアウトを挙げている。

本ライブラリとの対応:

- 座標指定の方式（`.sb-page--grid`）は、ブロック組みに当たる。
- 「見出しは最後」は、座標指定で記事の段数と行数を先に決め、見出しの大きさは後から調整する使い方に当たる。

### 10.9 禁止レイアウト

次は、割付の際に避けるべきレイアウト（禁じ手）。**本ライブラリが自動で防ぐものではない。**

あかつき印刷の説明（理由つき）:

| 呼称 | 内容 |
|---|---|
| 両流れ | 記事が、イラストなどの両側を流れる。読者が、どちらへ続くのかわからなくなる |
| 泣き別れ | 上段の最後が句点で終わり、下段の最初が改行で始まっているため、続きが読み落とされる。上段の最後の行から下段へ文章を送るか、上段の最後の行を一部削って下段を送り込む。囲みやタタミのように一つの枠の中に入っている場合は、さしつかえない |
| 飛びおり | 流し組みでは、記事は下段の右下または真下へ流れるが、上段より左へ流したり、二段も飛びおりたりする形は禁じられている |
| 飛びこし | 記事が何かを飛びこえて流れること。例外を除いてやってはならない |
| ハラキリ | 段と段の間が、紙面を横断すること。紙面の統一感を失い、見出しの直列や並列、両流れが起こりやすいなどの理由で、タブーとされる。タブロイド判などでは、あまり考える必要はない。下から二段目や一段目がハラキリになるのは、さしつかえない |
| 見出しの直列 | 見出しが縦に並んで、合計で何段もの見出しに見えること。紙面をタテに分断する |
| 見出しの並列 | 同じ位置の段に、同じ段数の見出しが並ぶこと。見出しの役割を相殺する。一段見出しの並列はかまわない。特集記事などで、並列させることに意味があれば別 |
| シリモチ | 紙面の最下段に、二段以上の見出しや写真などを配置すること。紙面のバランスをくずす。やむを得ないときは、上段の比重を重くしたり、横見出しにするなどの工夫が必要 |

パーソナル編集長の用語集の定義（呼称は出典のまま）:

| 呼称 | 定義 |
|---|---|
| エントツ | 見出しの真下に見出しを並べること |
| しりもち | 2 段以上の見出しや写真を最下段に配置すること |
| 横並び | 同じ大きさの見出しを同じ段に並べること |
| 飛び降り | 記事を上段より左に流したり、一段超えて流すこと |
| 飛び越し | 2 段以上の記事にまたがる写真を飛び越して流すこと |
| 泣き別れ | 記事が続いているのに、段末が改行で終わること |
| 両流れ | 記事が上段の 2 か所から下段に流れる可能性があること |
| ハラ切り | 段間が紙面の端から端まで通ってしまうこと |

JLReq 4.1.11 も、段抜きの別行見出しを段の末尾に配置してはならないと定めている。

### 10.10 文字組みの実験

宮崎紀郎・大橋透「新聞を主とした文字レイアウトの基礎的研究：1行あたりの字詰数と行間の検討」（『デザイン学研究』47, 1984）は、字詰数（10・15・20・30・40・60・80）と行間（1/1・1/2・1/4）の 21 通りの組み合わせで、30 秒間に読める文字数を測っている。写研細明朝体 11 級、文章は朝日新聞の「天声人語」、被験者は千葉大学の学生 47 名（読み取りは 44 名のデータを採用）。

- 一番速く読めたのは 30 字詰・行間 1/1、次いで 20 字詰・行間 1/2、15 字詰・行間 1/2 だった。
- 字詰数は、20〜30 字あたりをピークとし、それ以上でもそれ以下でも読み取り数が少なくなった。10 字詰は、極端に字数が少ないために、単語が途切れたり、一つの文章が何行にもまたがったりして、行をまたぐ視点の移動が多くなることが原因と考えられている。
- 行間については、はっきりした傾向が出なかった。字詰数が少ない場合は行間を狭く、字詰数が多い場合は行間を広くした方がよい、という概括は言えない、とされている。
- 結論として、同一量の文字を載せるなら、行間 1/1 は行間 1/2 に比べて多くのスペースが必要で不経済であり、限られた紙面で多くの情報を載せる新聞の本文に行間 1/1 を用いるのは妥当でない。新聞の効率のよい紙面利用を考えるなら、15〜20 字詰・行間 1/2 を本文に用い、30 字詰・行間 1/1 を見出しに続くリードに用いるのが適当、としている。

これは読みやすさを調べた実験の結論であり、実際の新聞の規格ではない。実際の新聞の 1 行は 10〜13 字（§10.2）。本ライブラリの既定の行送り `--sb-lh: 1.55` は、行間が約 1/2 に当たる。

## 12. 制限

- 一部の段にまたがる段抜き（記事の内側）は扱えない。`column-span` が `all` と `none` だけだからである。記事とは別の部品である `.sb-yoko` は、任意の段数を占められる。
- 記事の自動配置はしない。段数と位置は、作者が決める。座標指定でも、本文が長方形に収まるかどうかは作者が調整する（`findOverflow()` で検出できる）。
- 記事の本文を、飛び地（離れた領域）や L 字の領域へ流し込むことはできない。Zenn の記事（いなにわうどん）は、JavaScript でボックスの寸法を決め、収まる文字数を計測して分割する方法を示している。
- 縦組みの表は扱わない。表は横組みで表示する。
- 縦組みの紙面は、画面より広くなる。横スクロールを前提とする。
- 縦組みの本文では、欧文と数字が正立（`text-orientation: upright`）で並ぶ。回転させたい部分は `.sb-sideways` を使う。
- 文字は扁平にしない（§10.3）。
- 記事の中の段と段を区切る罫線（中段罫）は引かない。
- 特定の新聞社の紙面デザイン・書体・ロゴの再現は、非目標とする。題字の `.sb-nameplate__logo` には、利用者自身のロゴを入れること。
